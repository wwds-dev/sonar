SONAR — how it works

A market scanner and paper-trading terminal that tries very hard not to overstate what it knows. Live prices, live news, a probability model, and five studies that failed to find an edge — all reported plainly.

The one thing to understand first. SONAR reads real market data and real news, but every position is paper. There is no funded account, no wallet, and no route to real money anywhere in the code. It exists to show, transparently, how a model and a set of heuristics actually perform — which, so far, is no better than chance.

A Polymarket board used to sit here and was removed. Mirroring a market's own odds back at you is not analysis — there was no independent model behind any non-crypto row, so each one simply repeated the crowd. Dropping it also removed about 52MB an hour of downloads.

The Tooltips switch in the toolbar explains every number on hover.

The provider layer

Sources sit behind one interface with a capability (quotes / bars / FX / crypto), a tier (keyless or keyed) and an on-off switch. Requests walk the enabled providers in order and take the first that answers, so a vendor going down is a skipped provider rather than a broken app.

One real fragility, found by building this. Switch Yahoo off and crypto still resolves through CoinGecko and FX through Frankfurter — but equities return nothing. They have no keyless second source, so most of the watchlist depends on a single undocumented endpoint. A free Finnhub key closes that gap.

3The hourly model

Each hour Polymarket asks whether the BTC/USDT candle will close at or above its open. Part-way through, the open o and current price c are known; the rest is modelled as a driftless random walk with per-hour volatility σ and remaining fraction τ:

P(up) = Φ( ln(c / o) / (σ · √τ) )
  • At the top of the hour (τ=1, c=o) it returns exactly 0.5 — no information, no edge.
  • As the hour runs out it collapses toward 1 or 0 on the current sign.

The only disagreement with the market comes from the volatility estimate: SONAR uses realised vol while the market prices its own implied vol. That is a real but thin edge, and frequently negative after the spread.

4The three numbers

Every Assets row carries three, and they answer different questions.

NumberWhat it means
CONF Notability, 0–100: news 0.35, momentum 0.30, catalyst 0.20, volatility 0.15. It ranks what is worth a look. It is not the odds of profit.
R:R Reward divided by risk, from a volatility-scaled target and stop. 1.5 means the target sits 1.5× as far away as the stop.
P(PROF) The probability of touching the target before the stop.
R:R and P(profit) are the same number twice. For a driftless walk the barrier maths fixes the hit rate at stop/(target+stop), so P(profit) = 1/(1+R:R) and EV = P·target − (1−P)·stop = 0 exactly. A fatter target buys a proportionally lower hit rate. No arrangement of barriers creates profit — only drift does, and drift has to be measured before it is used.

That is why P(PROF) reads a flat 40% across the board and is drawn in grey: with R:R fixed at 1.5 and no measured edge, that is the honest number. It moves only when calibration finds real drift.

There is deliberately no Bullish/Bearish lean. There used to be; the research below found the momentum behind it was worth nothing, so it was deleted rather than tuned. The NEWS column shows how unusual today's coverage is — Quiet / Normal / Elevated / Spike — which is a notability flag and not a direction.

5The paper book

buy and short open a paper position on any row, sized so that being stopped out costs a fixed slice of the book. Two very different instruments therefore risk the same cash at their stops, which is the only sizing rule that treats them comparably. One position per symbol.

Exits are prices, not dates: the target and the stop. History says those resolve in a median of 6 trading days, a quarter inside 3 and three quarters inside 10.

Optionally through Alpaca

The built-in book fills instantly at the quoted price with no fees and no queue, which makes it an optimistic bound. Alpaca's paper environment is more honest — real market hours, real order handling, orders that sit unfilled when the market is shut. Add a free paper key to a git-ignored .env and SONAR uses it:

APCA_API_KEY_ID=PK...        # paper keys start with PK
APCA_API_SECRET_KEY=...
On the guards. Alpaca's live and paper APIs differ by one hostname. The host is a module constant with no parameter to override; a key that is not clearly a paper key is refused before any request; the account is checked on connect; and every request re-checks all of it. Each failure raises. Going live is not a setting in this app — it is a decision for a human with an account, and SONAR does not implement it.

6How the score gets graded

Every closed position carries the confidence it was opened on, so the Book tab can ask the only question that matters: did high scores actually win more often? Hit rate is bucketed by score and compared with what the barrier maths advertised.

Below 20 closed positions it reports nothing at all. A five-win streak is not an edge, and a young install showing an empty table is the honest state rather than a bug.

The run backtest button answers the same question in seconds instead of months, by replaying the identical plan over years of real bars — momentum and volatility from prior bars only, then walking forward through actual highs and lows. A bar that spans both barriers scores as a loss, since daily data cannot order them, and costs are excluded. Reality is worse than what it reports, not better.

7What the research found

Five studies, each more careful than the last. All of them negative.

QuestionAnswer
Does momentum predict the barrier outcome? No — flat across buckets, and worse than baseline for the largest moves.
Does a news/attention spike? No — +0.8 points against a ±3.1 error bar, over 25,504 setups.
Does anything sort the cross-section? No — 0 of 16 features survived false-discovery correction over 116,563 rows.
Did the one surviving lead replicate? No — it lived in a single period, appeared in crypto rather than the equities its theory requires, and had no orderly decay.
Does anything work conditionally? No — 0 of 48 feature-by-regime tests, with the floor set by a control.
The most useful thing the research produced was a warning. In one holdout window a seeded random number — a feature that cannot predict anything — reached t = −1.87, while real features sat at +2.4 to +3.4 and looked like discoveries. Daily cross-sections are correlated, so a single window holds far fewer independent observations than its date count suggests. Candidates are now scored against the noise floor measured in their own window, never a textbook threshold.

An earlier version of these docs claimed a news spike was worth +4.9 points. It did not survive a larger sample and fell to +0.8. That claim is recorded as withdrawn rather than quietly deleted, because silently editing it would leave exactly the false impression this project exists to argue against.

Two things are still untested, not cleared: SONAR's own word-list sentiment (Wikipedia pageviews measure attention volume, not tone), and anything requiring intraday or order-flow data.

8Running it & what it costs

A native macOS app — PySide6 widgets, every chart drawn with QPainter, no web view.

uv venv .venv && uv pip install -r requirements.txt
python main.py              # the app
python main.py --selftest   # check a build's wiring and exit
python main.py --headless   # the HTTP daemon instead

Does it cost money?

No. It runs locally, every source is a free public API with no key and no billing, it places no real trades, and the running app makes zero AI/LLM calls — the model is local arithmetic and the news sentiment is a local word list. Building SONAR used AI; running it does not.

The only resource is bandwidth, roughly 8MB an hour since the Polymarket board was removed — down from about 60MB. Negligible on broadband, and worth knowing on a metered connection.

9Honesty & limits

This is not financial advice and it places no real trades. Paper P/L predicts nothing about real results. Live trading means real fees, real spread, real slippage and real risk — none of which a simulation pays.
  • No edge has been found. Five studies, progressively more careful, all negative. That is the expected answer for liquid instruments priced by people running the same arithmetic.
  • Confidence is notability, not the probability of profit. P(PROF) is that, and it sits at its driftless baseline because no drift has been measured.
  • Small samples lie. Dozens of positions cannot separate skill from luck. An early run showed +114% on a 44% win rate, carried entirely by three longshot wins — variance wearing a costume.
  • News is context, never instruction. Scraped text is treated as untrusted data: read and summarised, never acted upon.
  • Fills are optimistic. The internal book ignores spread, slippage and fees; the backtest excludes costs and resolves ambiguous bars against you.

By design SONAR stops one step short of acting. It will take you up to a decision with its reasoning fully exposed, and leave the decision to you.
